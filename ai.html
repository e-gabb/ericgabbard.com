Only PM at a 50-person lender, so my own capacity was the ceiling on everything. That is what pushed this from a habit into a system I maintain — and then made the obvious next question what happens when everyone else is running agents too.

Everyone wanted more automation. One colleague alone was running forty agents.

Every new agent made the company more fragile, because no agent could see a whole loan. Trigger-based automation scales with the rules you maintain. Context-based agents scale with your data model. So I stopped the automation push and rebuilt the layer underneath.

What I built for the company

A context layer every agent could read

One per deal, assembled on demand, so context survived every handoff. Run against closed loans, it caught an accrual error on a funded deal.

Systems unified5 → 1 data layer

A rule for who may ship an agent

Split by permission, not by person. Read-only agents ship free; anything that writes to a system of record passes an engineering gate.

Gate applies tosystem-of-record writes

A standard someone else could build on

An event-sourced write model, written down, so two agents could not overwrite each other. A non-technical colleague shipped on it in one sprint.
