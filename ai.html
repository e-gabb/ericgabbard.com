AI

I build the AI systems I propose. At a 50-person lender: the context architecture our agents ran on, the standard a non-technical colleague shipped against in one sprint, and the rule for who was allowed to automate what.

Time to close −27% 26 → 19 days, on the data layer
Agent run cost −84% ~$32 → ~$5 a day, same workflow
Systems unified 5 → 1 one authenticated agent data layer
Second builder 1 sprint non-technical, shipping conformant agents

Everyone wanted more automation. Every new one made the system more fragile, because no automation could see a whole loan. Trigger-based automation scales with the rules you maintain. Context-based agents scale with your data model. So I stopped the automation push and rebuilt the layer underneath — the work that also took time to close from 26 days to 19.

What I built

Deal context architecture · Jun–Aug 2026

One context layer per deal, assembled on demand, so context survived the handoff from sales to processing to underwriting. Run against closed loans, it caught an interest-accrual error on a deal that had already funded. I demoed that catch to the executive team. Our engineering lead had argued for a database; I showed the specific case instead of the principle, and got the call.

The write model · Jun 2026

Single writer, two agents, silent data loss — found at five deals and one agent, the cheapest possible moment to fix it. Locking manages the collision. Event sourcing removes it.

Then I wrote the standard down. A non-technical colleague shipped conformant agents on it the same sprint, without me correcting them into the pattern after.

The governance model · Apr–Jul 2026

Every team was told to build agents; one colleague alone was running forty. Lock it down and you kill the momentum that made it valuable. So: split by permission, not by person. Read-only ships free. Anything that writes to a system of record goes through a gate.

The gate before the gate · Jul 2026

Governance says who may ship. It does not say whether the thing should be an agent at all. My test: an agent earns its place on judgment over messy input. Same input, same destination, every time? That is code, and it belongs to engineering. It shipped as the first gate in our agent-authoring tool.

Cost is a design decision · Jul 2026

Our first multi-agent workflow ran ~$32/day naive. I took it to ~$5 — incremental off events, batched, cached, with the cheap model doing extraction and the expensive one only judgment. On the next agent I priced two designs before writing code and shipped the one 40% cheaper. Designed and handed off; it had not gotten a deploy slot before my role ended.

Deal-loss analysis · Jul 2026

Loss reasons came from a dropdown, and a fifth of them landed in "Other." I built a read-only agent that re-derives the reason from the deal's own evidence. First run: two deals recorded as losses were not losses — the borrower had been rerouted to another product internally. We had been understating conversion.

The operating system I ran the job on · 2026

Only PM at a 50-person company, so my capacity was the ceiling on everything. 30+ custom Claude Code skills wired to six live data sources, plus scheduled jobs that ran overnight and wrote back with citations. Teammates started building on the same foundation.

What I run now

Between roles it did not stop, which is the honest test of whether any of it was real. A vault that ingests and cross-links my notes nightly. A curator that mines each day's work for improvements. A council of adversarial agents I convene on my own decisions.

This page was rebuilt from one of those runs. It told me I had buried the evidence under three hundred words of philosophy, so I cut the philosophy.
