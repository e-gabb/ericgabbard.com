A weekday, end to end

Most of my work happens before I open the laptop.

First drafts of research, analysis, and specs arrive in hours, from agents I built against six live data sources, on a schedule that runs whether or not I’m awake.

Overnight

Every note I took, cross-linked against everything before it.

Before 9

Scheduled agents have reported

Six live systems pulled into one brief, every claim cited.

The workday

Agents take the first pass

Research, analysis, specs, prototypes. That is how the first version gets made.

After hours

A curator agent mines the day

It proposes changes to the system itself. I approve them in the morning.

I was the only PM at a 50-person lender, so my own capacity capped what product could do. That is what pushed this from a habit into a system I maintain, and then raised the obvious next question: what happens when everyone else is running agents too?

Everyone wanted more automation. One colleague alone was running forty agents.

Every new agent made the company more fragile, because no agent could see a whole loan. Trigger-based automation scales with the rules you maintain. Context-based agents scale with your data model. So I paused new automations and rebuilt the layer underneath first.

What I built for the company

A context layer every agent could read

One per deal, assembled on demand, so context survived every handoff. Run against closed loans, it caught an accrual error on a funded deal.

Systems unified5 → 1 data layer

A rule for who may ship an agent

Split by permission, not by person. Read-only agents ship free; anything that writes to a system of record passes an engineering gate.

Gate applies tosystem-of-record writes

A standard someone else could build on

A written standard for how agents record changes, so two of them could not overwrite each other, and cheap enough to run that cost stopped being an argument against it.
